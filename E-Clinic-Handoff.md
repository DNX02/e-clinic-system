## Правила работы

- Сначала анализируй и тестируй, затем меняй код.
- Не выводи, не коммить и не загружай секреты, пароли, `DATABASE_URL` или содержимое базы пациентов.
- Не редактируй и не удаляй `data/db.json`: это локальная копия чувствительных данных.
- Перед production-изменением сделай резервную копию, проверь тесты и выполни smoke-check всех приложений.
- После проверенного изменения создай понятный commit и push в private GitHub remote.
- Платные облачные ресурсы, остановку Google Cloud или переключение DNS выполнять только после отдельного подтверждения владельца.

## Данные и текущий production

Production ранее работал на Google Cloud:

- VM: `e-clinic-server-recovery`, зона `us-central1-a`.
- PostgreSQL: Cloud SQL instance `eclinic-postgres`.
- В базе около 6.5 тысяч анкет медсестёр, 5 000 событий журнала и сотни учебных записей.
- На VM настроены ежедневные резервные копии Cloud SQL, PITR и резервные копии диска.
- Nginx проксирует приложения к Node.js.

В октябре 2026 были краткие OOM-перезапуски Node.js и PostgreSQL query timeouts. После снижения шумных 404, ротации логов и блокировки типичных probe-paths все health-проверки проходили успешно. Первопричина OOM не считается окончательно доказанной.

## Безопасный план миграции на AWS

1. Инвентаризировать Google VM, Cloud SQL, DNS, сертификаты, резервные копии и переменные окружения без вывода секретов.
2. Подготовить отдельную AWS VPC и security groups.
3. Создать минимальную тестовую среду: EC2 или App Runner + RDS PostgreSQL + S3 backups + CloudWatch/Budgets.
4. Перенести структуру и обезличенную тестовую выборку; затем выполнить контролируемый экспорт/импорт production-базы с проверкой количества записей и контрольных сумм.
5. Развернуть приложение, прогнать `npm ci`, `npm run test:product`, `npm run test:ui`, `node --check server.js` и smoke-check всех `/api/health`.
6. Настроить Route 53/Cloudflare и TLS, но не менять DNS до подтверждения владельца.
7. Провести пробный период через отдельный AWS hostname. Только после подтверждения переключить домены.
8. Сохранить Google Cloud как rollback минимум на несколько дней; не удалять Google VM, Cloud SQL и backups автоматически.
