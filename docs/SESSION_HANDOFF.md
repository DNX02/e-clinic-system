# Передача контекста между сессиями Claude

Последнее обновление: 12.11.2026. Читать вместе с `CLAUDE.md`.

## Как работаем
- Владелец общается на русском. Он не программист: объяснять просто, команды давать готовыми блоками.
- Изменения: правка → `npm run test:product`, `npm run test:ui`, `npm run test:e2e` → push в `main`
  (владелец разрешил) → автодеплой → проверить `/api/health` (`commit`) и `npm run check:prod`.
- При изменении `public/app.js`/стилей: поднять `CACHE_NAME` в `public/sw.js` (сейчас `medical-mobile-v98`)
  и `?v=` у `app.js`/`styles.css` во всех 7 HTML.
- Не трогать клинические пороги и формат `POST /api/nurse-surveys`.
- Данные пациентов не коммитить в репозиторий.

## Открытые задачи (не начаты, ждут решения владельца)
- **Бумажные анкеты** пациентов 23–30 (фото тетради): прочитаны, CSV был выдан владельцу; не хватало
  поликлиники, медсестры, курения, «высокого сахара». Загружает владелец через админку.
- Не исправлено из аудита: публичный `POST /api/nurse-surveys` без rate-limit; `rateLimits`/`securityAlertState` не чистятся;
  PBKDF2 100k итераций; данные граждан РТ хранятся в Швеции (вопрос локализации).
- **Cloudflare кэширует `/sw.js` на 7 дней** (`cache-control: public, max-age=604800`, хотя сервер отдаёт
  `no-cache`): 13.11.2026 на краю Cloudflare висел `medical-mobile-v94`. Страницы и `app.js?v=` обновляются
  нормально, но новый Service Worker доходит до телефонов с опозданием. Нужно правило в Cloudflare
  (Caching → Cache Rules: `/sw.js` — Bypass cache) и Purge для `/sw.js`. Делает владелец в панели Cloudflare.
- UX: скрипт Cloudflare Analytics блокируется CSP. Владелец отказался (18.11): rate-limit анкет, PBKDF2/очистка
  счётчиков, локализация данных, новый дизайн кабинета врача.
