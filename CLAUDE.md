# CLAUDE.md — Руководство по проекту E-Clinic (Medical QR System)

## 1. Обзор проекта и архитектура
**E-Clinic** — цифровая медицинская платформа для первичного скрининга неинфекционных заболеваний (сахарный диабет 2 типа, артериальная гипертензия, сердечно-сосудистые риски) и диспансерного учёта в амбулаторных поликлиниках г. Душанбе (Республика Таджикистан, Минздрав РТ).

- **Архитектура бэкенда:** Vanilla Node.js (нативный модуль `node:http`, без фреймворков Express/Nest), `server.js` (монолитный API, маршрутизация, аутентификация по сессиям/токенам, валидация, расчёт рисков, экспорт PDF/Excel).
- **Архитектура фронтенда:** Vanilla JS (ES Modules) без сборщиков (Webpack/Vite). Все страницы лежат в `public/`, общее ядро приложения — `public/app.js`.
- **PWA и офлайн:** Поддержка полного офлайн-скрининга у участковых медсестёр через Service Worker (`public/sw.js`) и двухуровневое хранилище очереди (IndexedDB `nurse_surveys` + резерв в `localStorage`).
- **База данных:** PostgreSQL 16 (JSONB-структуры с B-tree индексами по ключевым путям) на AWS Lightsail (`eu-north-1`). При отсутствии `DATABASE_URL` сервер автоматически переключается на локальный файл `data/db.json`.

## 3. Переменные окружения (Environment Variables)
- `PORT` — порт веб-сервера (по умолчанию `3000`).
- `DATABASE_URL` — строка подключения к PostgreSQL (например, `postgresql://user:pass@host:5432/eclinic`). Если не задана, данные читаются/пишутся в локальный `data/db.json`.
- `TELEGRAM_BOT_TOKEN` — токен бота для алертов мониторинга и вечерней сводки.
- `TELEGRAM_REPORT_CHAT_ID` — ID чата Telegram для ежедневных отчётов.

## 4. Клинические правила и пороги (НЕ МЕНЯТЬ без согласования с Минздравом)
1. **FINDRISC (шкала риска СД2):**
   - 0–6: Низкий
   - 7–11: Слегка повышенный
   - 12–14: Умеренный (12 и 13 баллов сами по себе **не направляют** к врачу)
   - **≥ 14 баллов:** Устанавливается `highRisk: true`, пациент направляется к врачу («Направить к врачу»).
2. **Артериальное давление (АД):**
   - САД ≥ 140 мм рт.ст. или ДАД ≥ 90 мм рт.ст. -> подозрение на АГ, автоматическое направление к врачу.
3. **Глюкоза крови:**
   - Натощак ≥ 6.1 ммоль/л (или случайная ≥ 11.1 ммоль/л) -> подозрение на СД2, направление к врачу.
4. **Сердечно-сосудистый риск (ВОЗ):**
   - Упрощённый скрининговый индекс (возраст, пол, САД, курение по нелабораторной шкале ВОЗ). Порог высокого риска: `points >= 5 || systolic >= 140`.
5. **Формула Рабито (Rabito):**
   - Антропометрический расчёт веса при отсутствии весов: окружность плеча, талии, голени.

## 5. Офлайн-синхронизация и обратная совместимость
- Медсёстры работают на смартфонах через PWA (установлено на экран «Домой»).
- **Синхронизация очереди:**
  - Защищена от гонок между вкладками и событиями через мьютекс `syncNurseInFlight` и `navigator.locks.request("eclinic_sync_nurse")`.
  - Идемпотентность: клиент генерирует UUID `clientSurveyId`. Сервер подтверждает повторы ответом `{ ok: true, alreadySaved: true, id }`.
  - Ошибки 4xx помечаются `requiresEdit: true`, чтобы не крутить бесконечные ретраи.
- **Правило обновления кэша:**
  - При любых изменениях в `public/app.js` или стилях **обязательно** инкрементировать версию в `public/sw.js` (константа `CACHE_NAME`, например `medical-mobile-v95`) и query-параметр скрипта `app.js?v=...` во всех 7 HTML-файлах (`admin.html`, `doctor.html`, `survey.html`, `investor.html`, `monitor.html`, `nurse-training.html`, `training.html`).
- **Обратная совместимость анкет:**
  - Нельзя менять названия и структуру существующих полей в `POST /api/nurse-surveys`, так как в офлайн-очередях на телефонах медсестёр могут лежать неотправленные анкеты старого формата.

## 6. Защита данных и регуляторика
- **Юрисдикция:** Республика Таджикистан (г. Душанбе).
- **Законодательство:** Закон РТ №1564 «О защите персональных данных», Закон РТ «Об охране здоровья граждан», нормы врачебной тайны Минздрава РТ.
- **Безопасность (OWASP ASVS Level 2):**
  - Защита от IDOR (не возвращать чужие медицинские данные при совпадении ID или дубликатах).
  - Строгая привязка врачей к их поликлинике (`clinicKey`).
  - Однофамильцы разделяются по году рождения (`extractBirthYear`), не блокируя ввод 409-й ошибкой.

## 7. Процесс развертывания (Деплой)
- Репозиторий: `https://github.com/DNX02/e-clinic-system.git`, основная ветка `main`.
- Боевой сервер: AWS Lightsail (`13.63.64.38`, Ubuntu 24.04).
- Сервис: `e-clinic.service` (systemd).
- После пуша в `main` на сервере выполняется:
  \`\`\`bash
  cd /opt/e-clinic-system
  git fetch origin main && git reset --hard origin/main
  sudo systemctl restart e-clinic.service
  \`\`\`
